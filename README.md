# VEYRA antimudak

Локальный антивирус пользовательского уровня для Windows с реальным
ядром обнаружения (сигнатуры + эвристика + риск-движок), карантином,
мониторингом в реальном времени, контролем автозагрузки и USB.

Этот документ написан честно и без маркетинга — здесь прямо указано,
что реализовано полноценно, а что является упрощённой версией того,
что делают промышленные антивирусы, и почему.

## Установка и запуск (разработка)

```
pip install -r requirements.txt
python main.py
```

Работает на Windows 10/11. Часть функций (реестр автозагрузки, проверка
цифровых подписей, определение съёмных дисков) специфична для Windows
и на других ОС либо отключается, либо возвращает "Не проверено".

## Сборка в .exe

```
build_exe.bat
```

Нужно запускать **на Windows** — PyInstaller собирает exe под ту
платформу, на которой выполняется, кросс-сборка из Linux ненадёжна.
После сборки готовый файл будет в `dist\VEYRA antimudak.exe`.

## Что реализовано по-настоящему

- **VEYRA Database** — SQLite с таблицами сигнатур, карантина, событий,
  настроек, истории сканирований, версией схемы.
- **VEYRA Scanner** — быстрая / полная / выборочная проверка, проверка
  файла, папки и критических системных областей, с прогрессом
  (файл, счётчик, найдено угроз, время, скорость).
- **VEYRA Database (сигнатуры)** — реальное вычисление SHA-256/SHA-1/MD5
  и поиск совпадений в локальной базе.
- **VEYRA Heuristic** — реальный анализ PE-файлов через `pefile`
  (нетипичная точка входа, секции упаковщиков, высокая энтропия секций,
  подозрительные комбинации импортов) и анализ скриптов (PowerShell/VBS/JS)
  на признаки обфускации и загрузки из сети.
- **VEYRA Risk Engine** — объединяет сигнатуры, эвристику, статус подписи
  и поведенческие флаги в балл 0–100 с объяснением причин, без выдачи
  вердикта по одному слабому признаку.
- **VEYRA Quarantine** — реальная изоляция файла (обфускация содержимого +
  смена расширения + ограничение прав), восстановление, удаление,
  сведения об объекте.
- **VEYRA Realtime** — реальный мониторинг файловой системы (watchdog /
  ReadDirectoryChangesW) в ключевых папках и мониторинг новых процессов
  через psutil, включая обнаружение всплеска массового изменения файлов
  (похоже на шифровальщик) и подозрительных параметров командной строки.
- **Автозагрузка** — реальное чтение разделов реестра `Run`/`RunOnce`
  (HKCU и HKLM) и папки автозагрузки, с оценкой риска и объяснением.
- **Цифровые подписи** — реальный вызов `WinVerifyTrust` через ctypes
  (без сторонних библиотек для этой части).
- **USB-контроль** — определение новых съёмных дисков и перечисление
  исполняемых файлов/`autorun.inf` на них (без автозапуска).
- **Обновление базы** — формат JSON с версионированием, проверкой
  структуры и (при наличии ключа) проверкой подписи Ed25519 перед
  установкой; повреждённые/более старые обновления отклоняются, при
  недоступности сервера работа продолжается на последней базе.

## Что упрощено или не реализовано — и почему

- **Нет драйвера ядра (minifilter).** Настоящая "проверка перед
  запуском" и блокировка "в момент попытки" в промышленных антивирусах
  делается перехватом на уровне драйвера файловой системы с подписью от
  Microsoft. Это отдельный, гораздо более сложный проект (WDK, EV-сертификат
  для подписи драйвера, тестирование на совместимость). VEYRA Realtime
  реагирует за доли секунды — секунды после события, а не строго до него.
- **Нет полноценной самозащиты на уровне процесса (PPL/защищённый
  процесс).** Реализован честный watchdog, который фиксирует в журнале
  факт недоступности компонентов защиты — это обнаружение постфактум,
  а не блокировка попытки остановки в реальном времени.
- **База сигнатур поставляется пустой.** VEYRA не включает готовую базу
  вредоносных хэшей на миллионы образцов — её ведение (сбор, проверка,
  обновление) это отдельная организационная задача, а не то, что можно
  честно "нарисовать" в демонстрационных целях. Модуль обновления готов
  принимать реальные обновления в описанном формате.
- **Ed25519-проверка подписи обновлений** требует библиотеки `pynacl` и
  реального ключевого пары (сервер подписывает, клиент проверяет
  публичным ключом). Пока публичный ключ не задан в `core/updater.py`
  (`VEYRA_PUBLIC_KEY_HEX`), обновления с включённой проверкой подписи
  будут корректно отклоняться — это ожидаемое поведение "по умолчанию
  недоверенно", а не баг.
- **Уведомления** используют библиотеку `plyer`; если она недоступна,
  уведомление просто не показывается (без имитации).

## Архитектура

```
core/          — конфигурация, БД, логгер, самозащита, обновления
detection/     — сигнатуры, эвристика, Authenticode, риск-движок
quarantine/    — карантин
scanner/       — сканер (все режимы проверки)
realtime/      — мониторинг файлов/процессов, USB
autostart/     — контроль автозагрузки
ui/            — интерфейс (tkinter, на русском)
main.py        — точка входа, связывает всё вместе
```

## Наполнение сигнатурной базы для тестирования

Пример добавления тестовой сигнатуры вручную (Python REPL):

```python
from core.database import Database
db = Database()
db.add_signature("<sha256_хэш>", "sha256", "VEYRA.Trojan.Generic", "Критическая угроза", source="manual")
```

## Права администратора

Для полного доступа к реестру HKLM, чтению всех процессов и некоторым
системным областям рекомендуется запускать `VEYRA antimudak.exe` от
имени администратора. Без этого приложение продолжает работать, но
часть данных (например, автозагрузка HKLM) может быть недоступна —
в интерфейсе это не подделывается пустым списком без объяснения,
а будет видно по факту отсутствия записей.
